# Forms (registration / feedback) + home-page announcement marquee

Replaces the Google-Forms links in the live site's scrolling bar
(`<a href="https://forms.gle/…">Click here to Register</a>`).

**Admin** can create any number of forms, each with a heading, optional
description and a list of questions; switch a form **Active / Inactive**; see
every submission in a table with search, date filters and CSV export.
**Public site**:

- a blue scrolling bar directly under the header menu on the home page shows
  **one entry per ACTIVE form**: its heading + "Click here to Register";
- the link opens the form's own page `/forms/<slug>`, visitors answer and
  submit — no login;
- inactive forms disappear from the bar and their page shows "This form is
  not available".

Feedback-style forms, not quizzes: there are no right/wrong answers and no
scoring.

Nothing on the backend exists for this yet. The whole flow (bar, form page,
admin list/builder/responses, CSV export) is built and was verified in a
browser against a mocked API that follows exactly the contract below, so
implementing this contract should work without frontend changes.

---

## 1. Data model

### `Form`

```js
{
  slug:        String,   // required, unique, lowercase; /^[a-z0-9]+(?:-[a-z0-9]+)*$/, 1–80 chars.
                         // Immutable after creation (shared links must keep working).
  title:       { en: String (required, 1–200), kn: String (default "") },
  description: { en: String (default ""), kn: String (default "") },   // ≤ 2000 chars each
  isActive:    Boolean,  // default true
  questions:   [Question],
  createdAt, updatedAt
}
```

### `Question` (embedded in `Form.questions`, order = display order)

```js
{
  id:        String,   // required, unique WITHIN the form, stable. Generated by the admin UI
                       // (e.g. "q_k3j9xa1"); the server must keep it as sent and never regenerate it,
                       // because responses reference it.
  type:      "text" | "textarea" | "radio" | "checkbox" | "select" | "rating",
  inputType: "text" | "email" | "tel" | "number",   // only meaningful for type "text"; default "text"
  label:     { en: String (required, 1–300), kn: String (default "") },
  helpText:  { en: String (default ""), kn: String (default "") },
  required:  Boolean,  // default false
  options:   [{ label: { en: String (required), kn: String (default "") } }]
             // only for radio / checkbox / select; ≥ 2 options, English labels unique (case-insensitive)
}
```

Suggested limits: ≤ 50 questions per form, ≤ 30 options per question.
`rating` is fixed 1–5 stars. Ignore `options` on non-choice types.

### `FormResponse`

```js
{
  form:      ObjectId (ref Form, required, indexed),
  answers:   [{
    questionId: String,   // id of the question at submission time
    question:   String,   // SNAPSHOT of the English question text at submission time (set by the server)
    value:      Mixed     // string | [string] | number — see §3
  }],
  createdAt              // = submitted-at, shown and filtered in the admin
}
```

`answers` deliberately keeps the question text snapshot: an admin may edit or
delete questions after responses exist, and old responses must stay
readable. The admin table shows the form's current questions as columns plus
an extra column (labelled *"… (removed)"*) for any answered question that no
longer exists.

Indexes: `Form.slug` unique; `FormResponse { form: 1, createdAt: -1 }`.

## 2. Public endpoints (no auth)

### `GET /forms/active`

Returns **only active forms** for the marquee, in a stable order (newest
created first is fine):

```json
[
  { "id": "…", "slug": "emtp-mangaluru",
    "title": { "en": "Export Management Training Programme … Mangaluru, 26th–31st October 2026", "kn": "" } }
]
```

Only `id`, `slug`, `title` are needed (do not send questions). `[]` when none
— the bar is then hidden.

### `GET /forms/:slug`

Full form incl. `questions`, **only if `isActive`**. Unknown slug **or
inactive → `404 { message }`** (the page shows "not available" for any error).

### `POST /forms/:slug/responses`

```json
{ "answers": [
    { "questionId": "q1", "value": "Asha Rao" },
    { "questionId": "q4", "value": "Yes" },
    { "questionId": "q5", "value": ["Documentation", "Finance"] },
    { "questionId": "q7", "value": 4 }
] }
```

- Behind the existing `publicWriteLimiter`.
- `404` if the form doesn't exist **or is inactive** (a visitor may have
  loaded the form before it was deactivated — the page handles the 404).
- `201 { "message": "Response received" }` on success.
- Unanswered optional questions are simply **omitted** from `answers`.

Server-side validation (never trust the client) — `400 { message }`
otherwise (the message is shown to the visitor):

| Rule | Detail |
|---|---|
| Known questions | every `questionId` must exist in the form; reject unknown ids; each id at most once |
| Required | a `required` question must be present with a non-empty value |
| `text` | string, trimmed, ≤ 300 chars; `inputType` `email` → valid email; `tel` → `/^\+?[\d\s()-]{7,20}$/`; `number` → numeric |
| `textarea` | string, trimmed, ≤ 2000 chars |
| `radio`, `select` | string equal to one option's **English label** |
| `checkbox` | array of ≥ 1 distinct strings, each an option's English label |
| `rating` | integer 1–5 |
| Body size | overall `answers` length ≤ number of questions |

Choice answers are submitted (and stored/exported) as the option's **English
label**, so the admin table and CSV are human-readable. On save, store the
snapshot `question` (English label) with each answer.

## 3. Admin endpoints (`requireAuth`)

| Method & path | Body → Result |
|---|---|
| `GET /admin/forms` | → array of summaries (below), newest first |
| `GET /admin/forms/:id` | → full form incl. `questions` (`404` if missing) |
| `POST /admin/forms` | full form (JSON) → `201` created form. `409 { message }` if the slug is taken |
| `PUT /admin/forms/:id` | full form (JSON) → updated form. **Ignore any `slug` change** (immutable) |
| `PATCH /admin/forms/:id` | `{ "isActive": true \| false }` → updated summary |
| `DELETE /admin/forms/:id` | deletes the form **and all its responses** → `{ message }` |
| `GET /admin/forms/:id/responses` | → array of responses, **newest first** (`createdAt` desc) |
| `DELETE /admin/forms/:id/responses/:responseId` | → `{ message }` (removes spam/test rows) |

`GET /admin/forms` summary shape (counts via aggregation/`countDocuments`):

```json
{ "id": "…", "slug": "…", "title": { "en": "…", "kn": "" }, "description": { "en": "", "kn": "" },
  "isActive": true, "questionCount": 8, "responseCount": 42, "createdAt": "…", "updatedAt": "…" }
```

`GET /admin/forms/:id/responses` item shape (`id` = `_id`):

```json
{ "id": "…", "createdAt": "2026-09-30T10:42:13.001Z",
  "answers": [ { "questionId": "q1", "question": "Full name", "value": "Asha Rao" } ] }
```

Admin `POST`/`PUT` payload (validated with the same limits as §1):

```json
{ "title": { "en": "…", "kn": "" }, "description": { "en": "", "kn": "" },
  "slug": "emtp-mangaluru", "isActive": true,
  "questions": [
    { "id": "q_k3j9xa1", "type": "text", "inputType": "email",
      "label": { "en": "Email", "kn": "" }, "helpText": { "en": "", "kn": "" }, "required": true },
    { "id": "q_b0djn9g", "type": "radio",
      "label": { "en": "Existing exporter?", "kn": "" }, "helpText": { "en": "", "kn": "" }, "required": true,
      "options": [ { "label": { "en": "Yes", "kn": "" } }, { "label": { "en": "No", "kn": "" } } ] }
  ] }
```

Notes for `PUT`:

- Keep each question's `id` exactly as sent. Editing a form **never**
  touches existing responses.
- The admin can change option text after responses exist; old responses keep
  the text that was stored at the time.

## 4. Acceptance checks

1. Create a form in **Admin → Forms → Create Form** (short answer, long
   answer, single choice, multiple choice, dropdown, rating; some required) →
   it appears in the list, **Active**.
2. Home page: the blue bar under the menu shows the heading + "Click here to
   Register"; hovering pauses it; clicking opens `/forms/<slug>`.
3. Submit with missing required answers → field errors (client side); a
   direct API call with a missing required answer, an option that doesn't
   exist, a rating of 9 or an invalid email → `400`.
4. Valid submit → *Thank you*; the response appears in **View responses**
   with a column per question, newest first.
5. Responses page: search, "Today / Last 7 days / Last 30 days" and custom
   date range, newest/oldest toggle, paging, detail drawer, delete;
   **Export CSV** → *All responses* and *Current results (with filters)*.
6. Toggle the form **Inactive** → it disappears from the bar,
   `GET /forms/<slug>` is `404`, `POST …/responses` is `404`; existing
   responses are kept; toggling **Active** restores everything.
7. Delete a form → its responses are gone too.
8. Edit a form after responses exist (rename a question, delete another) →
   old responses still display; the deleted question shows as an extra
   "(removed)" column.

## 5. Recommended / optional

- **Rate limit + duplicate guard** on `POST …/responses`: reject the same
  answers from the same IP within a short window.
- **`closesAt` (Date, optional)**: auto-close a form after a date without
  the admin remembering to toggle it; treat as inactive after that instant in
  `GET /forms/active`, `GET /forms/:slug` and the POST. (Not built into the UI
  yet — tell us if you want it.)
- **Email notification** to an admin inbox for each response (mailer exists),
  and/or an **acknowledgement email** to a respondent who filled an email
  question.
- **Server-side paging/filtering/CSV** for responses when a form gets
  thousands of rows: `GET …/responses?from=&to=&q=&page=&limit=` →
  `{ items, total }` and `GET …/responses/export`. The UI currently loads all
  rows and filters / exports in the browser (fine up to a few thousand).
- **Response cap** per form (`maxResponses`) for limited-seat trainings.
