# Market Data releases (Exporter Corner → Market Intelligence)

**Supersedes** [05-market-intelligence.md](./05-market-intelligence.md). The old
`state-exports`, `top-products` and `country-products` collections held static
data scraped from the old site (₹ Crore, by HS-code product). The VTPC team now
has real, regularly updated DGCIS/RBI workbooks (**US$ million**) with a
different shape — district, sector and state level rather than HS-product
level — and **staff will upload a new workbook every quarter** from the admin
panel. This doc defines the storage and endpoints for that.

The admin UI (`/admin/market-data`) and the public section are already built
against the contract below.

## How it works (end to end)

1. Staff open **Admin → Exporter Corner → Market Data**, download the **Excel template**
   (`public/templates/VTPC-Market-Data-Template.xlsx`, a static file served by the frontend — no
   backend work), fill in one period's figures, and upload the `.xlsx`. The original DGCIS
   workbooks are accepted too, unchanged.
2. **The browser reads and validates the workbook** (same parser as
   `scripts/importMarketIntelligence.mjs` in the frontend repo) and shows a
   preview. The period (e.g. `Q1 FY 2026-27`) is read from the sheets
   themselves; files from two different periods are rejected.
3. On "Publish", the browser sends **one JSON document** (a *release*) to
   `PUT /admin/market-releases/:key`.
4. The public site lists releases (`GET /market-releases`) and loads the one the
   visitor picks (`GET /market-releases/:key`).

> **The backend does not parse Excel.** It stores and validates JSON. That keeps
> the server free of spreadsheet libraries and means the exact same document can
> be produced by the CLI script for seeding.

One release = one period (`FY 2025-26`, `Q1 FY 2026-27`, `Q2 FY 2026-27`, …).
Uploading a period that already exists **replaces** it; a different period adds
a new one. Old periods stay available until an admin removes them.

## The Excel template (frontend-owned, for context)

The template has a "Read me" sheet plus `Period`, `Districts`, `Sector by District`, `Sector by State`
and `Countries (optional)`. Only `Period` + `Districts` are required; a sheet left blank is simply
treated as "not provided", and the matching website tab is hidden. It is generated by
`npm run build-market-template` in the frontend repo and parsed by the same code as the DGCIS
workbooks, so **whatever staff upload always reaches you as the JSON below** — the server never
sees Excel, and a layout change to the template never needs a backend change.

## 🔴 New resource: MarketRelease

```
GET    /market-releases                 public — list, newest period first, WITHOUT the heavy data
GET    /market-releases/:key            public — one full release
PUT    /admin/market-releases/:key      auth + permission `marketData` — create or replace (upsert)
DELETE /admin/market-releases/:key      auth + permission `marketData`
```

`:key` is the period slug, e.g. `fy-2025-26`, `q1-fy-2026-27` (`^(fy|q[1-4]-fy)-\d{4}-\d{2}$`).

### List item — `GET /market-releases`

```json
[
  {
    "key": "q1-fy-2026-27",
    "label": "Q1 FY 2026-27",
    "type": "quarter",
    "previousLabel": "Q1 FY 2025-26",
    "counts": { "districts": 30, "sectors": 22, "states": 8, "countryRows": 0 },
    "updatedAt": "2026-10-05T10:48:00.000Z"
  }
]
```

**Ordering (important — the UI shows the first item by default):** newest period
first. Sort by financial-year start year descending, then by quarter descending
with the full-year release sorting **after** its quarters of the same year
(`Q2 FY 2026-27`, `Q1 FY 2026-27`, `FY 2025-26`, …). Compute a numeric
`sortOrder` on save, e.g. `fyStartYear * 10 + (type === "year" ? 0 : quarter)`.

`counts` is computed by the server on save (lengths of the arrays below).

### Full release — `GET /market-releases/:key` and the `PUT` body

Real, ready-to-import samples generated from the actual workbooks:

- [`data/market-intelligence/releases/fy-2025-26.json`](./data/market-intelligence/releases/fy-2025-26.json) (annual; includes countries; ~390 KB)
- [`data/market-intelligence/releases/q1-fy-2026-27.json`](./data/market-intelligence/releases/q1-fy-2026-27.json) (quarterly; no countries; ~40 KB)

```jsonc
{
  "key": "q1-fy-2026-27",
  "type": "quarter",                    // "quarter" | "year"
  "label": "Q1 FY 2026-27",
  "previousLabel": "Q1 FY 2025-26",     // the period every "previous" value belongs to
  "unit": "USD Mn",                     // always US$ million
  "source": "DGCIS, Kolkata",
  "totals": { "previous": 9431.443784, "current": 9978.830127 },   // Karnataka goods, sum of districts

  "districts": [                        // required, 1+ items
    { "name": "Bengaluru Urban", "previous": 2477.235838, "current": 3213.159871,
      "variation": 29.71,               // % change, null when previous is 0
      "majorProducts": "Turbo-Jets of A Thrust>25 Kn, other Medicine put up for Retail Sale, …" }
  ],

  "states": ["All India", "Karnataka", "Tamil Nadu", "…"],         // [] when the workbook has no state sheet
  "stateTotals": {                                                 // goods only (services excluded)
    "Karnataka": { "previous": 9431.492081, "current": 9978.845154 },
    "Telangana": { "previous": null,        "current": 3628.082061 }   // previous may be null
  },
  "sectorStates": [                     // [] when absent
    { "sector": "Electronics & Semiconductor", "isServices": false,
      "values": { "All India": { "previous": 11928.06, "current": 14166.0 },
                  "Karnataka": { "previous": 2631.95,  "current": 2846.86 } } }
  ],
  "sectorDistricts": [                  // [] when absent; only non-zero districts are listed
    { "sector": "Electronics & Semiconductor", "isServices": false,
      "hsCode": "85 -(8501, 8504, 8537,8544)", "total": 2846.86,
      "values": { "Kolar": 1487.539103, "Bengaluru Rural": 1061.02017 } }
  ],
  "countryDistricts": [                 // [] for quarterly releases (the workbook has no country sheet)
    { "district": "Bengaluru Urban", "country": "United States", "previous": 2700.517044, "current": 3068.648385 }
  ]
}
```

Notes for the model/validation:

- All money values are **US$ million**, plain numbers (not strings). Rounded to 6 decimals by the client.
- `previous` can be `null` (a state whose last-period figure isn't in the workbook); `current` is never null.
- District / state / sector / country **names are already cleaned** by the client
  (e.g. `"U S A"` → `"United States"`, `"Chamaraja nagara"` → `"Chamarajanagara"`)
  and are used as-is as display text and as lookup keys inside the document.
  The server stores them verbatim.
- `isServices: true` is the *Software & Services Exports* row (an RBI estimate).
  It is shown separately from goods on the site and **excluded from all goods totals**.
- `sectorDistricts[].values` keys are always district names that exist in `districts[].name`.
- This is **one document per period**, written/read as a whole — do not normalise it into many collections.

### Suggested Mongoose model

```js
const mongoose = require("mongoose");
const { apiJson } = require("./plugins/apiJson");

const figure = { _id: false, previous: { type: Number, default: null }, current: { type: Number, default: null } };

const marketReleaseSchema = new mongoose.Schema(
  {
    key: { type: String, required: true, unique: true, match: /^(fy|q[1-4]-fy)-\d{4}-\d{2}$/ },
    type: { type: String, enum: ["quarter", "year"], required: true },
    label: { type: String, required: true, trim: true },
    previousLabel: { type: String, required: true, trim: true },
    sortOrder: { type: Number, required: true, index: true },   // computed on save, see "Ordering"
    unit: { type: String, default: "USD Mn" },
    source: { type: String, default: "DGCIS, Kolkata" },
    totals: figure,
    districts: [{ _id: false, name: String, previous: Number, current: Number, variation: { type: Number, default: null }, majorProducts: { type: String, default: "" } }],
    states: [String],
    stateTotals: { type: Map, of: new mongoose.Schema(figure) },
    sectorStates: [{ _id: false, sector: String, isServices: Boolean, values: { type: Map, of: new mongoose.Schema(figure) } }],
    sectorDistricts: [{ _id: false, sector: String, isServices: Boolean, hsCode: { type: String, default: "" }, total: Number, values: { type: Map, of: Number } }],
    countryDistricts: [{ _id: false, district: String, country: String, previous: Number, current: Number }],
    counts: { _id: false, districts: Number, sectors: Number, states: Number, countryRows: Number },
    updatedBy: { type: String, default: "" },
  },
  { timestamps: true }
);

apiJson(marketReleaseSchema);
module.exports = mongoose.model("MarketRelease", marketReleaseSchema);
```

Map keys: state/district names contain spaces but no `.` or `$`, which Mongo disallows
in keys. If a name ever contains `.`, reject it with a 400 (see validation).

> Mongoose `Map`s serialise to plain objects with `toJSON({ flattenMaps: true })`
> — make sure the `apiJson` plugin does that, otherwise the public GET returns `{}`.

## Validation (server must enforce — never trust the client)

`PUT /admin/market-releases/:key` → `400 { message }` when:

1. `:key` doesn't match the pattern, or `body.key !== :key`.
2. `type` isn't `quarter`/`year`, or `type`/`key` disagree (`q…` ⇒ quarter, `fy-…` ⇒ year), or `label`/`previousLabel` is empty.
3. `districts` is empty, or any district has a non-numeric `current`/`previous`, or two districts share a name.
4. Any money value is not a finite number (`NaN`, strings, `Infinity`).
5. A name used as an object key contains `.` or starts with `$`.
6. Any `sectorDistricts[].values` key isn't in `districts[].name` (guards against client/server drift).
7. Payload > ~5 MB (the global `express.json` limit is 10 MB, which is enough: the annual sample is ~0.4 MB).

On success: upsert by `key`, set `sortOrder`, `counts` and `updatedBy`, return `200` with the list-item shape.
Replace means replace — do **not** merge arrays with the previous version of the same period.

## Permissions & audit (see doc 18)

- New permission key **`marketData`** → page "Market Data" (`/admin/market-releases*`). Add it to the
  permission catalog in doc 18 §1 (sidebar group *Exporter Corner*). Super Admin implicitly has it; the
  default **Editor** role should get it so nobody loses access.
- Both `PUT` and `DELETE` must write an audit log entry, same helper as the bulk-replace endpoints:
  `record(req, { action: "update"|"delete", resource: "marketData", target: { id: key, label }, summary: "Published Q1 FY 2026-27 (30 districts, 22 sectors)" })`.
  Don't store the full payload in `before/after` — log the summary and counts only.
- Public `GET`s need no auth and no permission.

## Seeding & retiring the old endpoints

- Seed the two sample files above (`npm run seed:market` can be re-pointed at `releases/*.json`)
  so the Exporter Corner page has data on day one.
- `GET /state-exports`, `/top-products`, `/country-products` and their `bulk-replace` routes are no longer
  used by the frontend. Leave them in place for now; remove them after this ships (they are listed as
  Super-Admin-only in doc 18, which can then drop that line).

## Out of scope

- Server-side Excel parsing (deliberately client-side — see above).
- Editing individual figures in the admin UI. To correct a number, fix the Excel and re-upload the period.
- `.xls` (old Excel format) — the admin asks staff to save as `.xlsx`.
